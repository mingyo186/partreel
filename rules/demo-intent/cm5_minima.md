## 0. 30초 요약

- CM5를 **바닥면**에 얹고 위쪽 면 전체를 M.2 SSD가 덮는 샌드위치 구조. 54.5 × 57.1 mm 안에 6층으로 밀어 넣었다.
- 커넥터는 **네 변에 기능별로 분배**: 왼쪽=전원/USB/이더넷, 아래=HDMI/I2C, 오른쪽=카메라FFC/버튼/LED, 위=M.2.
- 배치의 1순위는 **CM5 커넥터 핀 위치**다. CM5 고속핀 옆에 있는 HDMI·USB는 13~20 mm로 짧고,
  핀이 반대쪽에 있는 이더넷·MIPI는 34~42 mm를 가로질러 간다 — 즉 "짧게"보다 "모듈 핀맵"이 우선했다.
- 전원은 전부 **존(폴리곤) 기반**, GND는 트랙이 사실상 0 mm에 비아 279개로 스티칭. 고속선은 외층에만.

### 1.1 스택업과 층 역할

| 층     | 유전체(위쪽)   | 역할(README) | 실측 트랙 길이 | 해석                                  |
| ------ | -------------- | ------------ | -------------- | ------------------------------------- |
| F.Cu   | —              | SIG:PWR      | 1124.1 mm      | 고속 신호 + 전원 존                   |
| In1.Cu | 0.0994 prepreg | GND          | 0 mm           | **F.Cu 전용 리턴 평면**               |
| In2.Cu | 0.5 core       | SIG-PWR      | 619.5 mm       | 저속 제어신호 전용 + GND 채움         |
| In3.Cu | 0.13 prepreg   | PWR          | 128.1 mm       | +5V / M2_3V3 전원 평면                |
| In4.Cu | 0.55 core      | GND          | 0 mm           | **B.Cu 전용 리턴 평면**               |
| B.Cu   | 0.0994 prepreg | SIG:PWR      | 911.8 mm       | 고속 신호(이더넷·PCIe CLK) + CM5 패드 |

**핵심 해석 [추정]**: 외층(F/B)만 GND 평면과 0.0994 mm로 붙어 있다. 즉 얇은 마이크로스트립이 되는 층은 F와 B뿐이고,
In2는 위로 0.5 mm(GND), 아래로 0.13 mm(PWR)라 사실상 전원면을 기준으로 삼는다.
그래서 **차동쌍 20쌍이 전부 F.Cu/B.Cu에만** 있고 In2에는 GPIO·LED·EN·nRST 같은 저속선만 있다 — 층 배정이 우연이 아니다. **[근거: 넷별 층별 길이 집계]**

### 1.2 넷클래스(임피던스 타깃)

| 클래스  | 패턴                                                 | 트랙 폭  | 차동 폭/간격 | 적용 대상                                 |
| ------- | ---------------------------------------------------- | -------- | ------------ | ----------------------------------------- |
| Default | —                                                    | 0.15 mm  | 0.178 / 0.25 | 일반 신호                                 |

**[추정]** 이 보드에서 **가장 빠른 신호(PCIe Gen2/3)가 가장 긴 배선**이다. M.2 카드가 22 × 42 mm를 요구해 위쪽 끝으로 밀렸고,
CM5 HSS 커넥터는 왼쪽 중앙에 있어 대각선 이동이 불가피했다 — 기구 제약이 전기 최적을 이긴 사례.

## 4. 전원 사슬

```
USB-C J101 (VBUS 5V)
  │  C101,C102 100n  /  R101 2k2 방전  /  TP101(+TP105 GND)
  └─► +5V  [F.Cu 존 + In3.Cu 존, 트랙 30mm·비아 31개]
        ├─► CM5 Module301 핀 77/79/81/83/85/87 (6핀 병렬 급전)
        ├─► U701 AP22653W6 (EN←CM5 VBUS_EN, ILIM 15k≈1.74A)
        │      └─► VBUS_USB2.0 ─► USB701  [C702 100µF 탄탈 + C703 10µ]
        ├─► U405 STMPS2151 (EN=+5V 상시)
        │      └─► HDMI_+5V ─► J501 핀18  [C502 100n]
        ├─► U702 AP3441 벅 (EN←CM5 PCIE_PWR_EN, R704 100k 풀다운)
        │      └─► L701 2.2µH ─► M2_3V3 ─► J701 3.3V ×9핀
        │             [C708~C711 10µ×4 + C712 100n, In3.Cu 존]  └─► U703 32.768kHz
        └─► J601 팬 5V

CM5 출력 ─► +3V3_PI (Module301 핀 84/86)  ─► LIS3DH, J502/J503/J802, RJ45 LED, I2C 풀업
CM5 출력 ─► +1V8    (Module301 핀 88/90)  ─► R103(DNP)만 — GPIO_VREF 옵션
CN1 (코인셀) ─► +BATT ─► CM5 VBAT (RTC 백업)
```

**흐름 해석 [추정]**

1. **전원은 한 방향으로만 흐른다.** 입력(왼쪽 중앙) → +5V 존 → 각 부하 스위치 → 소비처. 되돌아오는 5 V 분기가 없다.
2. **모든 하위 레일에 스위치나 레귤레이터가 하나씩 붙는다.** USB 포트=AP22653(전류제한), HDMI=STMPS2151(전류제한), M.2=AP3441(강압). 세 개 다 **CM5 또는 상시 신호로 인에이블 제어** → 부팅 순서를 SoC가 잡는다.
3. **3.3 V를 자체 생성하지 않는다.** CM5의 PMIC 출력(+3V3_PI)을 그대로 받아 쓴다. 캐리어 보드 부품 수를 줄이는 대신 CM5 전류 한계(주석 "600 mA Max")에 묶인다.
4. **전원은 트랙이 아니라 존이다.** +5V는 트랙 30 mm뿐이고 F.Cu·In3.Cu 존으로 흐른다. M2_3V3도 F.Cu + In3.Cu 존 + 최대 3.0 mm 폭 트랙. 우선순위(priority 0~10)를 겹쳐 써서 같은 층에서 존이 서로 파고들게 했다.

**핵심 [근거]**: 20개 차동쌍 중 **In1/In2/In3/In4 내층으로 내려간 것이 하나도 없다.** 전부 F.Cu 아니면 B.Cu.
내층 In2는 GPIO·SPI·EN·nRST·LED·CC 같은 저속선 619 mm만 담당한다.

**정리한 관례 [근거]**

4. **출력 벌크는 뭉치지 않고 부하로 분산.** M2_3V3의 10 µF 4개는 x 105~127에 흩어져 소켓 전원핀을 따라 배치.
5. **커넥터 입력부에도 캡을 둔다** (C101/C102, C401). 대형 벌크(전해/탄탈)는 USB 포트 출력(C702 100 µF)에만 — 핫플러그 대응 지점에 집중.

## 10. 이 보드에서 배울 수 없는 것 (한계)

- **PD/충전 협상**: 보드에 PD 컨트롤러가 없어 CC 로직 설계 사례로는 못 쓴다.
- **3.3 V 생성**: CM5 PMIC 출력을 받아 쓰므로 LDO/벅 3.3 V 설계 관례는 M.2 레일(AP3441) 하나뿐.
- **길이 튜닝(serpentine)**: 배선 길이가 이미 잘 맞아 사행 배선 패턴 사례가 없다.
- **임피던스 실측 근거 없음**: 넷클래스 값이 타깃일 뿐, 스택업 대비 계산/시뮬 결과는 파일에 없다. 폭·간격 값을 그대로 재사용하면 안 된다. **[추정]**
