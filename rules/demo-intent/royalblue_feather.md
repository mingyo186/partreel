# RoyalBlue54L-Feather 설계 의도 심층 분석 (KiCad 10 데모, 8층)

- 대상: `D:\Program Files\KiCad\10.0\share\kicad\demos\royalblue54L_feather\`
  (`RoyalBlue54L-Feather.kicad_sch` / `.kicad_pcb`, 하위 프로젝트 `nfc_antenna/RoyalBlue54L-NFC-Antenna`)
- 출처: Lord's Boards, rev 0.0.1 (2025-01-25), CERN-OHL-V2-P, Crowd Supply 판매 보드
- 분석 방법: 회로도 4장 s-expression 직접 파싱 → `kicad-cli sch export netlist`로 넷리스트 확정 →
  `.kicad_pcb`를 s-expression으로 파싱해 **패드 절대좌표(풋프린트 회전 반영)** 재계산 →
  거리·배선길이·비아·존(zone) 경계 실측. 주요 IC는 웹으로 데이터시트 확인.
- 좌표 표기: KiCad 원좌표(mm). 보드 외곽 = **X 119.10~177.52, Y 93.55~116.41**
  (즉 **58.42 × 22.86 mm** = 2.30″ × 0.90″). Y는 아래로 증가.
- 표기 규약: 실측으로 확인한 것은 그대로, 근거가 정황뿐인 것은 **[추정]** 으로 표시.

## 2. 층 구성 — "모든 신호층에 0.1 mm 레퍼런스"

8층 / 1.6 mm / FR4 Er=4.5 / ENIG / **castellated_pads = yes**

| 순서 | 층 | 용도(실측 존/배선) | 아래 유전체 |
|---|---|---|---|
| 1 | F.Cu   | 신호(로컬·USB쌍) + GND 채움 | 0.10 프리프레그 |
| 2 | In1.Cu | **GND 플레인** | 0.30 코어 |
| 3 | In2.Cu | VDD 채움 + 신호(I²C, A0~A5) / +BATT 채움 | 0.10 |
| 4 | In3.Cu | **GND 플레인** | 0.30 코어 |
| 5 | In4.Cu | VDD 채움 + 신호(PMIC I²C, CC, VBUS, 디지털) | 0.10 |
| 6 | In5.Cu | GND 채움 + 신호(UART, 아날로그, 디지털) | 0.30 코어 |
| 7 | In6.Cu | **GND 플레인** | 0.10 |
| 8 | B.Cu   | 신호(NFC 쌍, SWD, 헤더 탈출) + GND/VSYS 채움 | — |

유전체 배치가 **0.1 / 0.3 / 0.1 / 0.3 / 0.1 / 0.3 / 0.1** 로 대칭이고, 0.1 mm는 항상
"신호층 ↔ 인접 레퍼런스" 자리에 들어간다(F↔In1, In2↔In3, In4↔In5, In6↔B).
0.3 mm 코어는 레퍼런스끼리 벌릴 수 있는 자리에만 쓴다. 즉 **비싼(얇은) 프리프레그를
임피던스가 필요한 곳에만 배정**한 스택업이다. 총 1.3 mm 유전체 + 0.28 mm 동박 ≈ 1.58 mm.

- 관통비아만 사용 (F.Cu↔B.Cu): 0.45/0.30 ×154, 0.40/0.25 ×6, 0.35/0.25 ×23.
  **8층인데 매립/마이크로비아 0개** — 층수는 늘리되 공정 단가는 표준 관통비아로 묶었다.
- 배선폭: 신호 0.15, 전원 0.30, USB 쌍 0.10.
- DRC 하한: clearance 0.0762 (3 mil), 외곽 클리어런스 0.127, hole-to-hole 0.25, **DRC 예외 0건**.

## 3. 기능 블록별 배치 의도

### 3.0 전체 파티션 (X축 1차원)

```
X: 119.10 ────────────────────────────────────────────────────── 177.52 (보드 우측단)
   [USB-C J3]  [ESD U3 / TagConnect J8]  [디버거 U5+Y2]  [PMIC U2+L1]  [U6]  [플래시 U4]  [모듈 U1]  [안테나 키프아웃]
    121.4          128.6                    136.9          147.6      155.2    159.5      161.5~168.9   171.42~177.52
```

노이즈원(USB 커넥터·디버거·스위칭 레귤레이터)에서 안테나까지 **거리를 X축으로 단조 증가**시켰다.
- 벅 인덕터 L1 → 안테나 키프아웃 경계: **22.56 mm**
- 디버거 U5 → 키프아웃: 34.5 mm, USB-C 패드 → 키프아웃: **46.0 mm**

### 3.1 무선 모듈 + 안테나 (핵심)

실측:
- 모듈 코트야드 = **X 160.72~177.52, Y 99.48~110.48** (16.8 × 11.0 mm), 회전 **−90°**
- 모듈 안테나 키프아웃(풋프린트에 내장된 rule area): **X 171.42~177.52 × Y 99.48~110.48**
  = 6.10 × 11.00 mm, **8개 동박층 전부**에 대해 `tracks/vias/copperpour = not_allowed`
- `Cmts.User` 레이어에 "Antenna Keepout" 텍스트가 (174.42, 104.98)에 찍혀 있음
- **GND·VDD 채움 존의 아웃라인이 정확히 X = 171.42 에서 잘려 있음** (존 폴리곤 실측:
  GND `(118.06,91.53)-(171.42,118.53)`, VDD `(118.06,91.53)-(171.42,119.91)`)
- 키프아웃의 오른쪽 경계 **177.52 = 보드 외곽선 X** — 즉 안테나가 보드 끝에 정확히 플러시
- 모듈 Y 중심 104.98 = **보드 Y 중심** (93.55~116.41의 정중앙)

**왜 그 자리인가**
1. 안테나 키프아웃을 **보드의 물리적 끝**에 두어야 유전체·동박·주변 부품에 의한 detuning이
   최소가 된다. 그래서 모듈을 −90° 돌려 안테나 쪽이 보드 우측단을 향하게 했다.
2. 모듈 I/O 패드는 전부 X 161.47~168.92(= 보드 안쪽)에만 있고, **안테나에 가장 가까운
   패드열 X = 168.92는 전부 GND** (A1, B1, D1, E1, F1). 그리고 GND 비아가 그 5개 패드
   좌표 **(168.92, 100.93/101.83/103.63/104.53/105.43)** 에 정확히 박혀 있다.
   → 안테나와 I/O 사이에 **GND 벽 + 8층 관통 스티칭**을 세운 것. 동시에 이 GND가
   안테나의 카운터포이즈(대지면) 역할을 한다.
3. 채움 존이 키프아웃 경계에서 딱 끝나므로, **안테나 밑은 완전 무동박 / 그 직전까지는
   꽉 찬 접지** — 모듈형 안테나가 요구하는 전형적인 조건을 정확히 만족시켰다.

**폼팩터를 늘린 이유 [추정]**
- 표준 Feather = 2.0″ × 0.9″ (50.8 × 22.86). 이 보드는 **58.42 × 22.86 = 2.3″ × 0.9″**,
  즉 **정확히 0.3″ (7.62 mm = 헤더 피치 3칸) 길다**. 세로는 표준 그대로.
- 헤더 마지막 핀(J1 pin16, J2 pin12)이 **X = 171.17**, 키프아웃 시작이 171.42 —
  **간격 0.25 mm**. 헤더 핀 배열은 표준을 지키고, 그 뒤에 안테나 영역을 통째로 덧붙인 구조.
- 즉 "Feather 호환 핀 배열"과 "모듈 안테나 키프아웃"이 충돌하니까 **보드를 늘려서 해결**했다.

**위험/타협 [추정]**
- 마운팅홀 H2/H4가 (174.98, 96.09) / (174.98, 113.87) — **X는 안테나 영역 한복판**이고
  Y로만 3.39 mm 비켜 있다. 키프아웃 Y 범위(99.48~110.48)를 홀에 안 닿게 잡은 흔적은
  명확하지만, 여기에 **금속 나사·스탠드오프를 쓰면 안테나가 detune될 소지**가 있다.

### 3.2 크리스털

| 항목 | Y1 (32.768 kHz, LFXO) | Y2 (32 MHz, HFXO) |
|---|---|---|
| 위치 | (161.09, 98.23) rot 180 | (131.69, 110.20) rot −90 |
| 대상 IC | U1 모듈 XL1/XL2 | U5 디버거 XC1/XC2 |
| 패드 간 거리 | **4.88 / 5.41 mm** | **3.32 / 2.59 mm** |
| 배선 | **B.Cu**, 각 2비아, 6.68 / 5.28 mm | **F.Cu 단독, 비아 0개**, 5.73 / 4.01 mm |
| 로드캡 | **없음** (SoC 내장 가변 로드캡) | C18/C20 12 pF, 크리스털 패드에서 **약 1.2 mm** |
| 접지 | — | 4핀 패키지(2·4번 GND) + 3 mm 내 GND 비아 **6개** |

**의도 해석**
- **주파수가 높을수록 짧고 같은 층에**: 32 MHz는 비아 0개·3 mm 이내·같은 층으로 붙였고,
  32.768 kHz는 5 mm에 비아 2개를 감수했다. HFXO는 발진 안정도·EMI에 직결되지만
  LFXO는 저주파·고임피던스라 길이보다 **누설·노이즈 결합**이 문제라서 감수 가능한 타협이다.
- **Y1이 왜 B.Cu로 도느냐**: 모듈 LGA 패드가 X 161.47/161.72/162.62 열에 촘촘히 있어
  F.Cu 표면으로는 빠져나올 틈이 없다. 즉 **모듈 패드 밀도가 크리스털 배선층을 결정**했다.
- **로드캡 제거**: nRF54L 계열의 내장 가변 로드캡을 써서 부품 2개를 없앴다.
  32 MHz 쪽(nRF52833)은 내장이 없어 12 pF 2개가 그대로 남아 있다 — 같은 보드 안에
  두 방식이 나란히 있어 비교 사례로 좋다.
- Y1은 안테나 키프아웃에서 9.08 mm 떨어져 있고 벅에서 17.6 mm 떨어져 있다.

### 3.3 전원 / DC-DC (nPM1300 + L1)

토폴로지: `USB VBUS → nPM1300 (충전기+CC검출) → VSYS ↔ +BATT(JST-PH) → BUCK2 → JP1 → VDD`

- **BUCK1 미사용**: `U2.3 SW1` 미접속, `VOUT1`은 VSYS에 그대로 묶임. 인덕터 1개만 쓴다.
- **VSET2 = R4 330 kΩ → GND**: BUCK2 출력전압을 저항으로 설정 (VSET1은 GND 직결).
- **NTC 핀 GND 직결** = 배터리 서미스터 미사용 → 충전 온도감시 없음 [추정: 저가·소형 우선].
- **Rd(5.1 kΩ) 저항이 없다**: CC1/CC2가 PMIC로 직결되어 CC 종단·전류능력 검출을
  nPM1300이 내부에서 처리 → 부품 2개 + 실장면적 절감.

배치 실측 (전부 mm, 패드 중심 기준):

| 경로 | 값 | 해석 |
|---|---|---|
| 입력캡 C2/C3 (10 µF) → PVDD (U2.4) | **1.90 / 1.92** | 벅 입력 루프를 IC 양옆에서 대칭으로 짧게 잡음 |
| SW 노드 (U2.5 → L1.2) | **3.39** (배선 3.76 mm) | **F.Cu 단독, 비아 0개**, 폭 0.15→0.30 |
| L1 출력 → 출력캡 C8 (10 µF) | **1.51** | 리플 전류 루프를 인덕터 바로 옆에서 닫음 |
| C8/L1 → VOUT2 핀 (U2.32) | 7.59 | 상대적으로 김 — 아래 참조 |
| L1 주변 3 mm 내 GND 비아 | 4개 | (147.1,110.1) (147.1,110.9) (150.4,110.1) (150.7,108.7) |
| U2 EP(노출패드) 열비아 | **9개 관통** | QFN 패들이 8층 GND 전체에 직결 |
| U5 EP 열비아 | **16개 관통** | 디버거도 동일 원칙 |

**의도 해석**
- 벅에서 가장 중요한 건 **입력 루프(입력캡–PVDD–PVSS)** 와 **SW 노드 면적**이다.
  입력캡 2개를 1.9 mm로 붙이고 SW 노드를 3.8 mm·비아 0개·단일층으로 끝낸 것은
  교과서적이다. dv/dt가 큰 노드를 층 사이로 끌고 다니지 않았다.
- 반대로 **VOUT2 핀까지 7.6 mm**는 길다. 이건 실수라기보다 **JP1 절단 점퍼를
  넣기 위한 배치** [추정] — 출력 노드는 DC 성분이 지배적이고 리플은 C8이 이미
  1.5 mm에서 흡수하므로 감수 가능한 타협이다.
- **JP1을 B.Cu(뒷면)에 둔 것**: 앞면 부품을 안 건드리고 칼로 끊어 전류 측정/외부 급전이
  가능하다. 브리지된 솔더점퍼 = 기본 연결, 필요할 때만 절단.
- **L1의 자리 (148.86, 110.93)** — 보드 아래쪽 가장자리, J1 헤더 바로 안쪽.
  안테나에서 22.6 mm, 두 크리스털에서 17.6 mm 이상 떨어져 있다.
  즉 **가장 시끄러운 부품을 가장 예민한 부품들의 반대편 끝에** 놓았다.

### 3.4 USB + ESD

경로: `J3(USB-C) → U3(TPD3E001) → U5(nRF52833) D+/D−`

| 항목 | 실측 |
|---|---|
| ESD ↔ 커넥터 패드 | **D− 2.51 mm, D+ 3.99 mm** (커넥터 바로 다음) |
| ESD 연결 방식 | **인라인 관통** — 배선이 U3 패드를 통과함 (스터브 0) |
| ESD → 디버거 | 8.56 mm |
| D+ / D− 총 배선장 | **22.55 / 22.38 mm (Δ 0.17 mm)** |
| 쌍 피치 | **0.328 mm** (긴 구간에서 y=103.376 / 103.704) |
| 폭 | 커넥터 근처 0.15, 긴 구간 **0.10** → 갭 0.228 |
| 층 | F.Cu 주력(레퍼런스 = In1 GND, **0.1 mm 프리프레그**) + B.Cu 짧게 |
| 넷클래스 | 회로도 `netclass_flag`로 **USB_DIFF** 지정: width 0.125 / gap 0.2032 / clearance 0.2032 |
| ESD 채널 사용 | IO2=D−, IO3=D+, **IO1 미사용**, VCC=VBUS (레일 클램프 기준) |

**의도 해석**
- **ESD는 "커넥터 다음, 다른 어떤 것보다 먼저"**. 2.5~4 mm는 사실상 커넥터 붙박이다.
  그리고 **스터브 없이 배선이 ESD 패드를 관통**하게 해서, 보호소자 자신이 만드는
  임피던스 불연속을 최소화했다.
- 넷클래스 피치 0.125 + 0.2032 = **0.3282 mm** — 실제 배선 피치 0.328과 정확히 일치한다.
  즉 클래스로 피치를 규정하고 폭만 0.10으로 좁혔다.
- **[추정] 목표 Zdiff ≈ 90 Ω**: h=0.1 mm, Er=4.5, w=0.10, s=0.228 마이크로스트립 쌍이면
  단일단 65~70 Ω, 결합 고려 시 대략 85~90 Ω대가 나온다. nRF52833의 USB는 풀스피드(12 Mbps)
  뿐이라 엄밀히는 불필요하지만 **관례를 지켰다**.
- USB-C의 A/B 핀(D+/D−, VBUS, GND)을 모두 단락 → USB 2.0 전용 양방향 삽입.
- **TP5~TP8 (VBUS / CC2 / D+ / D−)** 이 커넥터 바로 뒤 X≈122.3~122.4의 B.Cu에 있다.
  차동쌍에 짧은 스터브가 붙는 셈이지만(B.Cu 3~5 mm), 풀스피드라 무해하다 — **디버깅
  접근성을 SI보다 우선한 의도적 타협**.

### 3.5 NFC

| 항목 | 실측 |
|---|---|
| 커넥터 J6 | (127.81, 114.53), 패드 X 125.81~129.81 / Y 113.28~115.78 — **보드 아래 가장자리 플러시** |
| 튜닝캡 C13/C14 (300 pF) | J6에서 **1.42 mm** (커넥터 쪽에 붙임) |
| 모듈까지 거리 | C13→U1.E8 **35.1 mm**, C14→U1.D9 **35.4 mm** |
| 배선 | **B.Cu 48 mm + F.Cu 2 mm, 각 2비아, 50.68 / 50.43 mm (Δ 0.25 mm)** |
| 경로 | J6 → 왼쪽 아래 → 대각선 → **보드 위쪽 가장자리(Y≈96.4/96.9)를 따라 X 135→154** → 대각선 → 모듈 |
| 쌍 피치 | 약 0.49 mm (폭 0.15 → 갭 0.34), 전 구간 평행 유지 |
| 자안테나 보드 | 별도 2층 23 × 58 mm, 0.3 mm 트레이스, F.Cu 345 mm + B.Cu 30 mm + 비아 2개 ≈ **2턴 루프** |

**의도 해석**
- 커넥터를 **보드 가장자리에 플러시**로 놓은 건 FPC 케이블을 케이스 밖/옆으로 빼기 위함.
- **위쪽 가장자리를 크게 돌아가는 경로**는 최단거리가 아니다. 보드 중앙에는 디버거·PMIC·
  레벨시프터가 꽉 차 있고, 중앙을 가로지르면 **벅 SW 노드(Y≈110) 근처를 지난다**.
  가장자리를 따라가면 스위칭 노이즈원과 최대한 멀어진다 [추정].
- 두 배선을 **0.5 mm 피치로 끝까지 평행**하게 유지하고 길이를 0.25 mm 이내로 맞춘 것은,
  13.56 MHz 루프의 **차동 대칭성**(공통모드 픽업 상쇄)을 지키려는 의도다.
  NFC는 임피던스 정합이 아니라 **공진**이므로 절대 길이보다 대칭이 중요하다.
- **튜닝캡을 SoC가 아니라 커넥터 쪽에 붙인 것**은 통상 권고(NFC 핀 근처)와 다르다.
  외부 FPC 안테나 구조에서는 어느 쪽이든 50 mm 배선이 공진 루프 안에 들어오므로
  큰 차이는 없지만, **캡–커넥터–안테나를 한 덩어리로 튜닝**하겠다는 선택으로 보인다
  [추정]. 재현 시에는 실측 튜닝이 필수.

### 3.6 디버거 / 테스트 접근

- **U6 TXB0106의 자리 (155.20, 104.92)** = 디버거(X 136.9)와 모듈(X 161.5) **사이 정확히
  전압 도메인 경계**. A측 = nRF52_VDD(디버거 내부 레귤레이터 출력), B측 = VDD(타깃).
- **OE 핀이 nRF52_VDD에 묶여 있다** → USB를 뽑으면 디버거 전원이 사라지고 OE가 내려가
  **모든 SWD/UART 라인이 Hi-Z**가 된다. "온보드 디버거가 타깃 핀을 절대 물고 있지 않게"
  하는 안전장치. (R1 100 kΩ이 nRF52_VDD를 GND로 당겨 레일을 빨리 방전 [추정])
- **J8 Tag-Connect(B.Cu)와 U3 ESD(F.Cu)가 좌표 (128.61, 104.97)로 완전히 동일** —
  앞뒤 면을 겹쳐 면적을 아꼈다. J8 풋프린트는 B.Cu에 **자체 rule area**
  (X 127.975~129.245 × Y 103.70~106.24, via/pour/footprint 금지)를 들고 있어
  포고핀 지그의 물리적 여유를 스스로 확보한다.
- 테스트 포인트 3세트 (전부 B.Cu):
  - **TP1~TP4** = 타깃(nRF54L15) SWDIO/RST/SWDCLK/GND — 모듈 바로 밑, **5.0 mm 정사각 격자**
  - TP5~TP8 = USB VBUS/CC2/D+/D− — 커넥터 뒤
  - TP9~TP12 = 디버거 VDD/RST/SWCLK/SWDIO — 2.4 mm 격자
  → 격자 피치를 맞춘 것은 **지그 포고핀 대응** 의도.
- 버튼 SW1(RST)/SW2(BTN)이 **둘 다 X = 155.76**, Y만 110.53 / 99.43 —
  보드 중심선(Y 104.98) 기준 **완전 대칭**. 양쪽 긴 변에서 손가락이 닿는다.
- I²C 풀업을 **버스 구간별로 분리 배치**: 외부 버스용 R2/R3는 Qwiic 커넥터 J5 옆
  (127.1/128.0, 100.85), PMIC 내부 버스용 R5/R7은 모듈 옆 (169.7, 111.13/112.07).

### 3.7 Feather 헤더 = 캐슬레이션

- 헤더 J1(16핀, B.Cu)·J2(12핀, F.Cu) 풋프린트는 **원형 스루홀 + 1.27 mm 옆으로
  치우친 사각 패드**를 함께 갖는다. 회전 반영해 계산하면 사각 패드가
  **정확히 보드 외곽선(Y 93.55 / 116.41)에 닿는다** → 반쪽 홀 = 캐슬레이션.
- 스택업에도 `castellated_pads yes`.
- 헤더 핀 열은 보드 가장자리에서 **1.27 mm(0.05″)** 안쪽 — Feather 표준.
- **의도**: 같은 보드를 ①핀헤더 꽂는 개발보드로도, ②캐리어 보드에 리플로우로 얹는
  모듈로도 쓸 수 있게 했다.

## 5. 정직한 한계

- 안테나 키프아웃의 치수(6.10 × 11.00 mm)는 **모듈 풋프린트에 이미 들어있던 값**이다.
  즉 이 보드 설계자가 계산한 게 아니라 **모듈 제조사(Fanstel) 권고를 그대로 받은 것**.
  따라서 RB2/RB3는 "모듈 권고를 어떻게 보드에 반영했는가"의 규칙이지,
  키프아웃 치수 산출 규칙은 아니다.
- Fanstel BM15x 데이터시트 원문(키프아웃 권고 수치)은 웹 검색으로 직접 확인하지 못했다
  (제품 페이지·기구도면까지만 확인). 풋프린트 rule area가 1차 근거.
- Zdiff 90 Ω, NFC 경로 선택 이유, Feather 0.3″ 연장 이유는 전부 **정황 추론**이다.
  설계자 문서(Crowd Supply 페이지/설계 노트)로 교차검증하면 확정 가능.
- 표본 1장이다. RB6/RB8/RB9 같은 수치 규칙은 다른 데모(One-Air-Max, StickHub,
  CM5_MINIMA)와 교차검증해야 일반 규칙으로 승격할 수 있다.

def rotp(x, y, deg):          # KiCad 풋프린트 로컬 → 절대

    return (x*math.cos(a) - y*math.sin(a), x*math.sin(a) + y*math.cos(a))
