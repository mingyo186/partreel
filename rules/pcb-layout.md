# PCB 배치 규칙집 (§25 2단계) — 기능: 보드 초기화/배치

회로도 가독 규칙집(schematic-readability.md)과 같은 방식 — 사용자와 보드를
만들며 확정한 규칙을 쌓고, 확정분은 build_pcb.py에 반영해 이후 보드에 자동
적용한다.

사용자 확정 규칙 (2026-08-10, g431_devkit 초기화 1차 검토 원문):
"원래는 외곽선을 넣어줘야 하는데 없으면 부품 수에 따라 정해야 하는 거야.
커넥터라는 건 보통 가장자리에 있다. SWD 같은 디버그 커넥터는 보통 MCU
근처에 있지 — 생산성을 위해 패드만 따로 뽑아서 떨어뜨려 놓기도 하는데
중소기업에선 보통 MCU 근처에 자리한다. 이번 USB는 패드 반대편이 외부
커넥터가 꽂히는 자리야 — 그래서 패드 반대편이 보드 외곽으로 향해야 해.
지금 니가 만든 건 보드 외곽 전체가 템플릿을 벗어났어 — 웬만하면 중앙으로
오게 하면 돼. 그리고 보드가 단층인지 2층인지 4층인지 확인을 받아야
설계하는 데 도움이 되겠지."

## P1. 보드 외곽 [board.json 선언 우선]
- 외곽(크기·모양)은 **사용자/보드 정의서가 주는 값이 우선**.
- 선언이 없으면 **부품과 배선 폭에 맞춰 최소화** — "부품이 다 들어갈
  정도의 크기만 있으면 된다. 부품과 선 넓이에 맞춰서 외곽선을 최소화"
  (2026-08-10 1차 구현이 널찍한 격자로 나가 교정받음).
- 외곽은 **용지 틀(템플릿) 안, 가운데**에 오게 그린다 — 틀 밖으로 나간
  외곽은 검토 자체가 불편하다.

## P2. 커넥터는 가장자리 [배치]
- 커넥터는 보드 가장자리에 붙인다.
- 삽입식(리셉터클: USB 등)은 **삽입구가 보드 밖을 향하게** — 패드가 있는
  쪽의 반대편이 외곽선에 닿는 방향.

## P3. 디버그 커넥터는 MCU 근처 [배치] — P2와 겹칠 땐 P3 우선
- SWD/STDC14 등 디버그 커넥터는 MCU 근처에 둔다 (중소기업 관례).
- 생산성 목적이면 패드만 따로 뽑아 떨어뜨리는 변형도 있으나 기본값은
  MCU 근처.

## P4. 층수는 설계 전 확인 [board.json 선언]
- 단층/2층/4층 여부는 설계 시작 전에 사용자에게 확인받는다 —
  board.json `layers` 필드로 선언 (배선·부품 밀도 판단의 전제).

## P5 (후보 — 사용자 확인 대기). 초기화 보드의 REF 글자는 Fab 레이어
- 최소 외곽 밀집 배치에서 실크 REF가 이웃 패드를 물어 DRC 19건 —
  초기화 단계에선 REF를 F.Fab에 두고, 실크 REF는 배치 확정 후 올린다.
  (소형 보드는 실크 REF 생략하고 조립도만 쓰는 관례도 있음)

## P6. 가장자리 접면은 부품 데이터에 표기 [확정 2026-08-10]
- "외곽선에 붙어야 될 부분을 부품에 표기해두는 게 좋겠어 — 다음 자동
  배치에도 실수를 안 하게." 삽입식 커넥터는 meta.parameters.edge_face에
  삽입구가 향하는 방향(+x/-x/+y/-y, 풋프린트 좌표계)을 적는다.
- 그런 부품은 **실크(몸체선)가 외곽선과 일치**하게 스냅한다 — id 추측이
  아니라 부품 데이터가 근거.

## P7. 기능 군집 배치 + 빈공간 최소화 [확정 2026-08-10]
- "부품과 연관된 부품은 메인 부품 근처에. IC가 중앙에 있고 사이드에
  수동소자들이 배치되고, 커넥터도 (연결된) IC 근처에. PCB 빈공간은
  최소화."
- 메인 IC(MCU) 군집을 중앙에, 나머지 블록 군집을 사방에 밀착 배치.
  가장자리 부품(P6)이 있는 군집은 해당 변에. 외곽은 군집 전체를 감싸는
  최소 크기.
